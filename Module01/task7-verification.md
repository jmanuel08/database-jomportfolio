Task 7: The First LLM-Assisted SQL Profiling Task

1. Prompt Used

Here is my SQLite table: readings(ts TEXT, machine TEXT, temp_c REAL, vib_rms REAL, spindle_load REAL). Write a SQL query that returns, for each machine, the average spindle load for readings taken overnight (after 18:00), ordered by average load descending. Explain how the query filters the time and groups the results.

2. SQL Query Generated by the LLM

SELECT
    machine,
    AVG(spindle_load) AS avg_spindle_load
FROM readings
WHERE time(ts) > '18:00:00'
GROUP BY machine
ORDER BY avg_spindle_load DESC;

5. Breaking the Query

I tested this incorrect filter:

SELECT COUNT(*)
FROM readings
WHERE ts LIKE '%18%';

Result: 18,102 rows

Then I checked how many matching timestamps occurred at or before 18:00:

SELECT COUNT(*)
FROM readings
WHERE ts LIKE '%18%'
  AND time(ts) <= '18:00:00';

Result: 8,538 rows

Finally, I tested the correct time filter:

SELECT COUNT(*)
FROM readings
WHERE time(ts) > '18:00:00';

Result: 43,194 rows

6. Verification and Reflection

The LLM generated a query that correctly calculates the average spindle load for each machine, filters readings strictly after 18:00 using time(ts), groups by machine, and sorts the averages in descending order. I verified the query by running it in SQLite and checking its execution plan. The plan showed SCAN readings and temporary B-trees for grouping and ordering. I also tested the incorrect LIKE '%18%' filter, which matched 18,102 rows, including 8,538 readings at or before 18:00. This demonstrated that searching for the characters 18 anywhere in a timestamp does not reliably filter readings by time.
